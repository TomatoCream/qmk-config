#+title: YK DO52 Pro — QMK config
#+date: 2026-11-13

Minimal QMK keyboard definition for the DO52 Pro (RP2040 split, integrated
ThinkPad TrackPoint). Only what is needed to build and flash is kept here; the
QMK checkout itself stays outside this repo.

* QMK source

=qmk_firmware/= is a git submodule pinned to the QMK revision this config was
tested with (=04c2dbd3df=). The submodule working tree is ~1.5 GB; the parent
repo history stores only the commit pointer.

#+begin_src bash
git submodule update --init --recursive
#+end_src

The =vusb= submodule is not needed for the RP2040 build; it may remain
uninitialized. =build.sh= uses =./qmk_firmware= by default.

* Requirements

- QMK from the submodule (=./qmk_firmware=). Override with =QMK_HOME= to use a
  different checkout (the script falls back to the old archive path when the
  submodule is absent).
- Nix. =build.sh= re-execs into =nix develop= when =arm-none-eabi-gcc= is not
  on =PATH=.

* Build

#+begin_src bash
./build.sh                 # VIA-enabled default keymap
QMK_HOME=/path/to/qmk_firmware ./build.sh
#+end_src

The script:

1. symlinks =keyboards/do52pro= into =$QMK_HOME/keyboards/=,
2. applies =patches/ps2_vendor-either-order.patch= if the checkout does not
   already support both PS/2 pin orders (current QMK master does), and reverts
   it after the build so the submodule stays clean,
3. runs =qmk compile -kb do52pro -km <keymap>=,
4. copies the UF2 to =firmware-rp2040/do52pro_trackpoint_<keymap>.uf2=.

* Formatting keymaps

=format-keymap.py= reflows every =LAYOUT_5x6(...)= call into the physical
grid: left half 5 rows × 6, right half 5 rows × 6 (its last row is the thumb
row), then the two 4-key DPAD rows. Columns are padded per layer so the commas
line up as a table; only line breaks, padding, and the group comments change —
keycode order is untouched.

#+begin_src bash
./format-keymap.py keyboards/do52pro/keymaps/default/keymap.c
./format-keymap.py --check keyboards/do52pro/keymaps/default/keymap.c
./format-keymap.py keymap.generated.c    # after via-export.sh
#+end_src

Files without a =LAYOUT_5x6= call are left alone. =--check= exits non-zero if a
file would change.

* Flash

#+begin_src bash
./flash.sh                 # newest UF2 in firmware-rp2040/
./flash.sh default         # explicit keymap name
./flash.sh firmware-rp2040/do52pro_trackpoint_default.uf2
#+end_src

Put one half in BOOTSEL (double-tap RESET, or hold BOOT while plugging USB),
wait for =RPI-RP2=, and the script copies the UF2. Flash the *same* file to
both halves.

- USB must be on the **right** half (the TrackPoint side); =MASTER_RIGHT=.
- Connect the TRRS cable *before* USB. Never hot-plug TRRS while powered.
- After flashing, unplug/replug USB so the TrackPoint power-cycles.

* VIA

The default keymap is built with QMK's VIA protocol and dynamic keymap
(=VIA_ENABLE = yes= in =keyboards/do52pro/rules.mk=). Build and flash once:

#+begin_src bash
./build.sh
./flash.sh
#+end_src

Then open <https://usevia.app> in Chromium/Edge (WebHID; on NixOS add
=pkgs.qmk-udev-rules= to =services.udev.packages=):

1. Settings → *Show Design tab*.
2. Design → *Load Draft Definition* → =keyboards/do52pro/via/do52pro.json=.
3. Configure → remap keys. Changes are written to the emulated EEPROM; no
   recompile or reflash.

The definition's =vendorId= /= =productId= must match =config.h=
(=0x594B:0x0D52=). VIA gets 4 dynamic layers by default; the C keymap has 3,
so layer 4 is transparent. =QK_RBT= /= =QK_BOOT= can be entered with VIA's
*Any* keycode.

** Export back to keymap.c

VIA edits EEPROM, not the C file. Save the layout from VIA's *Save + Load*
tab, then convert it:

#+begin_src bash
./via-export.sh ~/Downloads/do52pro.layout.json
# writes ./keymap.generated.c
./via-export.sh backup.json keyboards/do52pro/keymaps/default/keymap.c
# or write straight over the source (review the diff first)
#+end_src

A live dump of this board is committed at
=keyboards/do52pro/via/do52pro-live.layout.json=; it works as a converter
test without the keyboard attached:

#+begin_src bash
./via-export.sh keyboards/do52pro/via/do52pro-live.layout.json
#+end_src

The script runs =qmk via2json= then =qmk json2c=: VIA stores layers in matrix
order (12×6), and =via2json= maps them back to =LAYOUT_5x6= order. The output
is generated C: comments are gone and the transparent 4th layer is included;
trim or edit before committing.

** EEPROM
The dynamic keymap is seeded from =keymap.c= only on first boot. If you change
the C keymap and reflash, clear EEPROM first. With =MASTER_RIGHT= the master is
the right half, and Bootmagic's default =[0,0]= is that half's top-left key —
hold the right half's =6= key (global matrix =[6,0]=) while plugging in. The
keyboard resets EEPROM and jumps to the RP2040 bootloader. Otherwise the old
VIA layout stays in the EEPROM. Normal UF2 reflashing does not touch the 8 KB
wear-leveled EEPROM area at the top of flash.

* Hardware facts

| Item | Value |
|------+-------|
| MCU | RP2040 (Pro Micro footprint) |
| Split link | serial on =GP3=, PIO0 |
| TrackPoint CLK | =GP22= |
| TrackPoint DATA | =GP23= |
| PS/2 PIO block | PIO1 (=PS2_PIO_USE_PIO1=) |
| PS/2 pull-ups | 2× 4.7 kΩ on the right PCB |
| Reset RC | 100 kΩ + 2.2 µF on the right PCB |
| Mount rotation | =PS2_MOUSE_ROTATE 270= (90° mount + 180° axis reversal) |

PIO0 is owned by the split serial driver, which registers the same IRQ vector
as the PS/2 driver; hence =PS2_PIO_USE_PIO1=.

* Gotchas

** Do not reset the TrackPoint after init
=ps2_mouse_init()= already performs the full sequence:
=0xFF= reset → =0xAA= self-test → =0x00= device ID → =0xF4= enable data
reporting → =0xF0= stream mode. QMK calls =keyboard_post_init_kb()= *after*
that; sending another =0xFF= there leaves the TrackPoint alive but with data
reporting disabled, so it never sends a report. The hook in =do52pro.c= must
not touch PS/2.

** Pin order
=keyboard.json= uses =clock_pin=GP22=, =data_pin=GP23= (the stock harness).
This QMK revision's PIO driver only accepted =clock = data + 1=; the patch in
=patches/= backports the newer driver that accepts either adjacent order.
No wire swap is needed.

** Buttons
=MOUSEKEY_ENABLE = yes= is required for =KC_BTN1..3=; =PS2_MOUSE_ENABLE= alone
only provides pointer motion.

** Debug console
=CONSOLE_ENABLE= is off in =rules.mk=. Enable it and =qmk console= to see
=ps2_mouse= diagnostics.

** Single-axis corrections
=PS2_MOUSE_ROTATE= handles the mount. If only one axis is wrong, use
=PS2_MOUSE_INVERT_X= or =PS2_MOUSE_INVERT_Y= in =config.h= instead.

* Known-good state

Verified on the right half with =evtest= on =YK do52pro Mouse=: pointer motion
reports =REL_X=/=REL_Y=, axes match the physical stick, buttons work. The
default keymap is the 68-key =LAYOUT_5x6= translation of the ZMK do52pro
keymap (three layers).
